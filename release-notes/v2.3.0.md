# 2image v2.3.0

本次更新将此前在 `services/generation/` 中已实现的可靠性基础设施全部接入生产代码路径：`generate_image()` 现在内部通过 `GenerationOrchestrator` 调度多供应商，错误分类、取消令牌、截止期限、健康检查与熔断正式对所有生成请求生效；`safe_get_image()` 委托 `bounded_download()`，全链路下载受 25MB 流式上限约束；Provider 注册表改用 stable `provider_id` 作为 key，路由规则不再依赖 display name 文案。

## 主要更新

### 生产路径可靠性接入

- **`generate_image()` 内部使用 GenerationOrchestration**：原线性 fallback loop（`except Exception` + `time.sleep(0.5)`）替换为结构化编排器调用；取消令牌（CancellationToken）与绝对截止期限（Deadline）通过新增的可选参数 `token` / `deadline_seconds` 透传，未传参时行为与旧版完全一致（向后兼容）。

- **Provider 错误边界映射（`_wrap_provider_fn`）**：现有 providers 抛出的 `ValueError("需要 xxx API Key...")` 映射为 `ProviderAuthError` → 不再重试当前供应商，直接 fallback 至下一个；网络超时等瞬态错误映射为 `ProviderTransientError` → 按 RetryPolicy 指数退避重试后再降级。错误分类器从"存在但未被使用"变为生产路径实际生效。

- **CancellationToken 全链路接入**：`GenerationController` 为每个生成任务创建独立 token；新增 `cancel_generation()` 方法，在用户点击停止或重试等待期间可立即中断（`Event.wait()` 替代 `time.sleep()`）。

### 下载安全加固

- **`safe_get_image()` 委托 `bounded_download()`**：所有 17 个 provider 的图片下载自动继承 25MB 流式上限、Content-Type 白名单校验、分块读取超时控制、逐跳重定向 SSRF 验证；不再一次性将完整响应体加载至内存。

### Provider 身份与路由稳定化

- **Registry 改用 stable `provider_id`**：`ALL_PROVIDERS`、`PROVIDER_KEYS`、`IMG2IMG_PROVIDERS` 的 key 从 display name（如 `"硅基流动 SiliconFlow (★推荐)"`）改为 stable id（如 `"siliconflow"`），改名不再导致路由失效。新增 `resolve_provider_id()` 用于旧配置的向后兼容迁移。

- **`DEFAULT_ORDER` 显式列表**：替代 `list(FREE_PROVIDERS.keys())`（依赖 pkgutil 发现顺序），固定为 `FREE_PROVIDER_ORDER` 显式列表，默认优先级可预测。

### 测试与验证

- **新增端到端集成测试（`tests/test_integration_orchestrator_e2e.py`，6 项）**：覆盖认证错误不重试、取消令牌立即中断、截止时间触发、瞬态错误重试后降级、向后兼容无 token 场景。

- **Provider 测试更新**：`test_safe_get_image_*` 系列适配新的委托行为；`test_smart_router` 适配 stable ID 断言。

## 下载与安装

- **安装包**：下载 `text2image_pro_v2.3.0.exe`，运行后按向导安装。
- **便携版**：下载 `text2image_pro.exe`，无需安装即可直接运行。
- 现有用户的配置（`~/2image/config.json`）和历史记录（`~/2image/history.db`）完全兼容，无需额外操作。
