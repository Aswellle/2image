## Critical Findings (1)

### [CR-001] AppProtocol 已定义但从未被导入使用 — 死代码

**Location**: `ui/app_protocol.py:12-36`
**Dimensions**: Architecture, Testing
**Description**: `AppProtocol` 是一个包含 14 个成员的 Protocol 类，但代码库中没有任何文件导入或引用它。`HistorySidebar` 和 `MainContent` 均接受无类型的 `app` 参数，直接访问具体的 `App` 实例。
**Impact**: 面板-App 合约无编译期安全检查。无法使用 mock 编写单元测试。该 Protocol 文件是死代码，误导读者以为存在接口契约。
**Fix**:

1. 在 `sidebar.py` 和 `main_content.py` 中导入 `AppProtocol`，用作 `app` 参数的类型提示
2. 补充 Protocol 至覆盖面板实际调用的全部 30+ 个成员（当前仅声明 14 个）
3. 或拆分为 `SidebarProtocol`（~19 成员）和 `MainContentProtocol`（~22 成员）

### [HI-002] App 转发层掩盖了跨面板耦合（21 个属性/方法）

**Location**: `ui/app.py:131-164`
**Dimension**: Architecture
**Description**: `App` 维护了 11 个转发属性和 5 个委托方法，Sidebar 的右键菜单通过这些转发直接访问 `main_content` 的控件（`pt`、`pv`、`szv`、`_queue_panel`）。
**Impact**: `App` 充当接线板式的上帝对象。每次新的跨面板交互都需要一个新的转发属性，导致传递性控件知识泄露。
**Fix**: 在 `App` 上引入基于意图的编排方法（如 `_regen_from_prompt`、`_queue_from_prompt`），替代暴露原始控件。

## Medium Findings (8)

### [ME-001] HTML 导出 XSS：`title` 值在 `<b>` 标签中未进行 HTML 转义

**Location**: `ui/app.py:1518-1526`（`_finish_export`）
**Dimension**: Security
**Description**: `title = App._display_title(e)` 直接插入 HTML 而不使用 `html.escape()`。同一行的 `e['prompt']`、`e.get('translated','')`、`e.get('provider','')` 已正确转义 — 仅 `title` 遗漏。
**Impact**: 分享的导出 HTML 文件中的存储型 XSS。
**Fix**: `title = html.escape(App._display_title(e), quote=True)`.

---

### [ME-002] 日志注入绕过：`log_to_file()` 清理了错误的字符序列

**Location**: `services/logger.py:18`
**Dimension**: Security
**Description**: 清理代码使用字面量反斜杠-n/r 字符串（`"\\n"` 是两个字符 `\` + `n`），而非实际的控制字符（`"\n"` 是换行符 0x0A）。实际的换行符未经修改直接通过。
**Impact**: 用户可控的提示词文本通过 `self._log(f"── 开始: {prompt[:60]} ──")` 记录。包含实际换行符的提示词将注入任意日志行。
**Fix**: `safe = msg.replace('\n', '\\n').replace('\r', '\\r')`.

---

### [ME-003] Gemini Provider 错误信息泄露 API 响应数据

**Location**: `services/providers/gemini.py:157-166`（`_extract_image`）
**Dimension**: Security
**Description**: `_extract_image()` 抛出包含完整反序列化 API 响应体的 `ValueError`。这与代码库其他地方使用的 `_safe_error_text()` 模式不一致。
**Impact**: 意外的 Gemini 响应格式会被完整记录到磁盘，并可能显示在错误对话框中。
**Fix**: 在 `_extract_image` 中使用 `_safe_error_text()` 模式或摘要错误信息。

---

### [ME-004] `_on_body_resize` 每次 Configure 事件触发昂贵的 widget 遍历

**Location**: `ui/app.py:347-348`, `ui/sidebar.py:200-208`
**Dimension**: Performance
**Description**: `_on_body_resize` 每次 Configure 事件（窗口大小调整时以 60Hz 触发）调用 `_place_panels()`，该函数无条件执行 `_update_card_wraplength()`，对数百个 widget 进行 4 层深度遍历。
**Impact**: 加载 100+ 张历史卡片时，窗口大小调整期间出现可见卡顿和高 CPU 占用。
**Fix**: 为 `_on_body_resize` 添加防抖定时器（类似 `_on_prev_resize` 中的 50ms 模式）。

---

### [ME-005] 缩略图加载无限制并发线程生成

**Location**: `ui/sidebar.py:596`（`_load_thumb`）
**Dimension**: Performance
**Description**: `_refresh_hist()` 的每次调用为每张卡片生成一个守护线程用于缩略图加载 — `HIST_PAGE_SIZE = 100` 时可生成多达 100 个线程。无节流、信号量或线程池。
**Impact**: 在 HDD 上，100 个并发文件打开和 PIL 缩略图操作导致磁盘抖动和 UI 响应延迟。
**Fix**: 使用 `ThreadPoolExecutor(max_workers=4)` 或有界生产者-消费者队列。

---
